# 태그 기능 확정 명세 (spec-fixed)

> 원본: `spec-original.md` (기본 기능 정의서)
> 이 문서는 원본을 바탕으로 데이터 구조·UI·엣지케이스를 확정한 **구현 기준 문서**다. 구현 중 이 문서와 다르게 판단해야 하면 먼저 문서를 고친다.
> 결정 출처 표기: **[사용자]** 사용자가 직접 선택 / **[임의]** 사용자가 위임해 Claude가 결정 (나중에 바꿀 수 있음)

## 1. 기능 개요

노트에 문자열 태그를 붙이고 뗄 수 있다. 태그는 노트 편집 화면(`NoteEditor`, 이 앱의 "노트 상세 화면")에서 확인하고 편집한다.

## 2. 데이터 구조

| 항목        | 결정                                                                                    | 출처     |
| ----------- | --------------------------------------------------------------------------------------- | -------- |
| 저장 형태   | `Note`에 `tags: string[]` 필드 추가 (노트 안에 포함, 별도 `/tags` 리소스 없음)          | [사용자] |
| 순서        | 입력한 순서를 그대로 유지 (정렬하지 않음)                                               | [임의]   |
| 기존 데이터 | `tags`가 없는 노트는 `[]`로 취급. `api/notes.ts`에서 응답을 받을 때 `tags ?? []`로 보정 | [임의]   |
| 시드        | `db.json`의 기존 노트에 `tags` 필드를 추가 (예시 태그 포함)                             | [임의]   |

```ts
// src/types/note.ts
export interface Note {
  id: string;
  title: string;
  content: string;
  tags: string[];
  createdAt: string;
  updatedAt: string;
}
```

- 저장은 기존 API를 그대로 쓴다: 생성 `POST /notes`, 수정 `PATCH /notes/:id` (body에 `tags` 배열 전체를 넣음). 새 엔드포인트는 없다.
- 보정 위치를 API 계층으로 정한 이유: 컴포넌트마다 `note.tags ?? []`를 반복하지 않고, `Note` 타입의 `tags: string[]`(필수)이 실제로 항상 참이 되게 하기 위해서다.

## 3. 태그 값 규칙 (정규화·검증) [임의]

입력값은 아래 순서로 처리한다. 순수 함수로 `src/utils/tags.ts`에 둔다.

1. **정규화**: 앞뒤 공백 제거(`trim`), 맨 앞의 `#`은 모두 제거(`#react` → `react`), 연속 공백은 공백 하나로 줄임.
2. **빈 값**: 정규화 후 빈 문자열이면 무시한다(에러 메시지 없음).
3. **길이**: 최대 **20자**. 넘으면 추가하지 않고 메시지를 표시한다.
4. **금지 문자**: 쉼표(`,`)는 태그 구분자로 쓰므로 태그에 포함할 수 없다(입력 시 구분자로 처리됨).
5. **중복**: **대소문자를 무시하고** 비교한다(`React` = `react`). 이미 있으면 추가하지 않고 메시지를 표시한다. 저장되는 표기는 처음 입력한 그대로 유지한다.
6. **개수**: 노트당 최대 **10개**. 10개가 되면 입력창을 비활성화한다.

근거: 대소문자만 다른 태그는 사실상 중복이다. 그렇다고 소문자로 강제 변환하면 사용자가 입력한 표기가 바뀐다. 길이·개수 제한은 사이드바와 편집 화면 레이아웃이 깨지지 않게 하기 위한 값이다.

## 4. UI

### 4.1 위치와 구성 [임의]

`NoteEditor`의 **제목 입력과 구분선 사이**에 `TagInput` 컴포넌트를 배치한다. 생성 모드와 편집 모드 모두 같은 UI를 쓴다.

```
노트 편집
[제목                              ]
[react ×] [공부 ×] [태그 입력...    ]   ← TagInput
 이미 있는 태그예요                    ← 메시지 (있을 때만)
──────────────────────────────────
[내용 ...                          ]
```

- 태그는 **칩** 형태이고, 칩마다 × 삭제 버튼이 있다. 칩·입력창·메시지의 스타일은 `docs/design-system/components/tag.md`를 따른다.
- 입력창은 칩 뒤에 이어서 둔다. placeholder는 `태그 입력 후 Enter`이고, 10개가 되면 `태그는 최대 10개까지` 문구를 표시하고 비활성화한다.
- 메시지는 입력창 아래에 표시하고, 다음 입력이 시작되면 지운다. 기존 저장 흐름처럼 `alert()`을 쓰지 않는 이유는 타이핑 중에 자주 발생하는 검증이라 모달이 흐름을 끊기 때문이다.
- 색상과 모서리는 `src/index.css`의 `@theme` 토큰만 사용한다(`docs/design-system/`).

### 4.2 조작 [임의]

| 동작                              | 결과                                                                                                                      |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `Enter` 또는 `,` 입력             | 현재 입력값을 태그로 추가 시도(3장 규칙 적용), 성공하면 입력창 비움                                                       |
| 여러 값 붙여넣기 (`a, b, c`)      | 쉼표로 나눠 각각 추가 시도. 실패한 값은 건너뛰고 첫 번째 실패 사유만 표시                                                 |
| 칩의 × 클릭                       | 해당 태그 제거                                                                                                            |
| 입력창이 비어 있을 때 `Backspace` | 마지막 태그 제거                                                                                                          |
| **한글 조합 중 `Enter`**          | 무시한다(`e.nativeEvent.isComposing`이 true이면 처리하지 않음). 처리하면 마지막 글자가 중복 태그로 추가되는 버그가 생긴다 |
| `Enter` 처리 시                   | `e.preventDefault()`로 폼 제출이나 줄바꿈 같은 기본 동작을 막는다                                                         |

### 4.3 저장 시점 [임의]

- 태그는 `title`/`content`처럼 **`NoteEditor` 로컬 state**(`tags`)로 관리하고, **[저장] 버튼을 누를 때 함께 저장**한다. 태그를 하나 추가할 때마다 바로 API를 호출하지 않는다.
- [취소]를 누르면 태그 변경도 버려진다.
- 저장할 때 입력창에 확정되지 않은 텍스트가 남아 있으면, 유효한 경우 태그로 추가한 뒤 저장한다(입력 손실 방지). 유효하지 않으면 그 텍스트는 버리고 저장한다.
- 근거: 기존 편집 폼이 "로컬 state → 저장 버튼으로 일괄 반영" 패턴이라 일관성을 유지하고, 취소 동작도 자연스럽다.

### 4.4 목록(NoteItem) 표시

이번 범위에서 **표시하지 않는다**. 원본 스펙이 "노트 상세 화면에서 확인"만 요구한다. [임의]

| 파일                                 | 변경                                                                                                                                                                                                                                    |

| `src/test-setup.ts`                  | `@testing-library/jest-dom/vitest`로 변경 (Vitest `expect`에서 jest-dom 매처 타입이 잡히도록)                                                                                                                                           |

> **구현 중 변경**: 처음에는 입력값(draft)을 `TagInput` 내부 state로 두려 했다. 그런데 4.3의 "저장 시 남은 입력 포함"을 하려면 `NoteEditor`가 입력값을 알아야 해서, draft를 `NoteEditor`로 끌어올렸다.
> | `db.json` | 기존 노트에 `tags` 추가 |

- `TagInput`은 Context를 쓰지 않는 표시용 컴포넌트다(값과 `onChange`만 받는다). CLAUDE.md의 "자식은 표시 + 콜백" 규칙을 따른다.

## 6. 엣지케이스 정리

| 상황                          | 동작                                                             |
| ----------------------------- | ---------------------------------------------------------------- |
| `tags` 필드가 없는 기존 노트  | `[]`로 보정되어 정상 표시, 저장 시 `tags`가 채워짐               |
| 공백만 입력 / `#`만 입력      | 무시                                                             |
| `React`가 있는데 `react` 입력 | 중복 메시지, 추가 안 됨                                          |
| 21자 이상                     | 길이 메시지, 추가 안 됨                                          |
| 11번째 태그                   | 입력창 비활성화로 입력 불가                                      |
| 한글 조합 중 Enter            | 무시, 조합이 끝난 뒤 Enter로 추가                                |
| 저장 실패                     | 기존과 같이 `alert('저장에 실패했어요')`, 로컬 태그 state는 유지 |
| 다른 노트 선택 / 새 노트      | 동기화 `useEffect`가 tags를 바꾸고 입력창·메시지도 초기화        |
