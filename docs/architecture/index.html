5. 화면 상태 전이

App의 selectedNoteId와 isCreating 조합에 따라 메인 영역(NoteEditor)에 표시되는 화면이 바뀐다. 

stateDiagram-v2
  direction LR
  state "미선택
id=null, creating=false
안내 문구 표시" as Empty
  state "편집
id=X, creating=false
editNote" as Editing
  state "생성
id=null, creating=true
addNote" as Creating

  [*] --> Empty
  Empty --> Editing: onSelect(id)
  Empty --> Creating: onNewNote
  Editing --> Editing: onSelect(다른 id) / onDone
  Editing --> Creating: onNewNote
  Creating --> Editing: onSelect(id)
  Creating --> Empty: onDone (저장 성공 또는 취소)
  • 새 노트를 저장한 뒤에는 방금 만든 노트가 선택되지 않고 미선택 화면으로 돌아간다. App.handleDone의 "선택 상태 유지" 주석과 실제 동작이 다르다.
  • 선택된 노트를 삭제해도 selectedNoteId는 지워지지 않는다. 이때 selectedNote를 찾지 못해 폼에는 직전 값이 남는다.

6. 데이터 시퀀스

Context는 API 호출이 성공한 뒤에만 로컬 상태를 바꾼다. 낙관적 업데이트나 재조회는 하지 않는다. 

sequenceDiagram
  autonumber
  participant U as 사용자
  participant E as NoteEditor
  participant L as NoteList / NoteItem
  participant C as NotesContext
  participant A as api/notes.ts
  participant S as json-server

  Note over C,S: 초기 로드 (Provider 마운트 시 1회)
  C->>A: fetchNotes()
  A->>S: GET /notes
  S-->>A: Note[]
  A-->>C: setNotes · loading=false
  C-->>L: notes 재렌더

  Note over U,S: 저장 (생성 / 수정)
  U->>E: 저장 클릭
  E->>E: 제목 검증 · saving=true
  alt isCreating
    E->>C: addNote(title, content)
    C->>A: createNote · createdAt/updatedAt 채움
    A->>S: POST /notes
    S-->>A: Note (id 생성)
    A-->>C: setNotes([...prev, note])
  else 편집
    E->>C: editNote(id, {title, content})
    C->>A: updateNote · updatedAt 채움
    A->>S: PATCH /notes/:id
    S-->>A: Note
    A-->>C: setNotes(prev.map(...))
  end
  C-->>E: resolve
  E->>E: onDone() · finally saving=false
  Note right of E: 실패 시 alert('저장에 실패했습니다')

  Note over U,S: 삭제
  U->>L: 삭제 클릭 (stopPropagation)
  L->>C: removeNote(id)
  C->>A: deleteNote(id)
  A->>S: DELETE /notes/:id
  A-->>C: setNotes(prev.filter(...))
  Note right of L: 에러 처리 없음
